# A11b Synthea generation receipt

Status: **zero-model verifier implemented; no real release has been pinned or
generated by this slice**.

`a11b_generation_receipt.py` closes the gap between a claimed source-provenance
JSON object and the bytes that actually produced a candidate A11b source
population. Its public compiler accepts only:

1. a prospective Synthea generation spec;
2. the exact A11b power spec and verified power receipt; and
3. one self-contained artifact root.

It never invokes Synthea, a shell, an API, or a model. The generator runner is a
separate future boundary. The compiler reads every registered input and every
generated output once through no-follow file descriptors, then emits a
path-stable canonical receipt.

## Bound surface

The generation spec must pin:

- the `synthetichealth/synthea` release tag and 40-character commit;
- JAR path, SHA-256, and byte count;
- Java executable path, SHA-256, and byte count plus every other file in the
  staged Java distribution;
- Java vendor/version plus the registered
  `-XshowSettings:properties -version` probe bytes and argv;
- exact generation argv, seed, population, reference date, locale, timezone,
  and the complete `LANG`/`LC_ALL`/`TZ` environment;
- every configuration and module file by path, SHA-256, and byte count;
- the exporter settings and output root;
- output type and resource bounds; and
- the canonical A11b power-spec and power-receipt hashes.

The compiler independently verifies the power receipt and requires its derived
source population of **448 Patients** to match the invocation and output policy.
It rejects any missing or unregistered file, path traversal, symbolic link,
hard link, non-regular file, changed registered input, duplicate JSON key,
duplicate or missing Patient identifier, unregistered output suffix, byte/entry
bound violation, or output population other than 448.

The receipt includes ordered input hashes and raw-output content hashes with
logical output paths themselves hashed, an output content hash, a canonical
Patient-resource manifest hash without disclosing Patient identifiers or
Synthea file names, compiler dependency hashes, and explicit
`efficacy_artifacts_opened: false`, `gold_artifacts_opened: false`, and
`model_calls: 0` declarations. Two byte-identical artifact roots must compile to
byte-identical receipts regardless of their absolute paths.

## What this does not prove

The runtime probe is a receipt from the registered generation procedure, not a
hardware attestation. Independent review must still verify the exact upstream
release/commit, download source, JAR, runtime distribution, and capture method
before approving the prospective spec. This slice deliberately contains no
placeholder “official” hashes that could later be mistaken for a completed pin.
